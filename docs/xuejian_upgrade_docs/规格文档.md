# XueJian v2-vN 升级规格文档

> 本文定义后续 RAG 与多 Agent 升级的统一规格。它约束输入输出、状态、错误、权限和持久化边界。实现细节分别见《RAG升级技术文档.md》和《多Agent升级技术文档.md》。

## 0. 阅读方式

- 产品 / UI：重点读「1. 产品边界」「8. UI 展示」。
- 后端 / Rust：重点读「3. 数据权威」「5. Artifact」「7. 错误分类」。
- Python / Agent：重点读「2. Runtime」「4. Tool Spec」「6. Graph State」。

## 1. 产品边界

### 1.1 系统定位

XueJian 是本地优先的学习工具，不是通用 Agent 平台。

升级后的 AI 能力只服务：

1. 基于已导入资料的学习问答。
2. 基于资料证据的候选制卡。
3. 基于复习记录的学习诊断。
4. 复合学习任务的受控协作。

### 1.2 非目标

以下能力不进入 v2-v7 主线：

- 开放域联网问答。
- 自动改写用户文件。
- 自动修改复习计划。
- 任意工具调用。
- 多 Agent 自由对话。
- 保存完整文档正文、完整 prompt、完整 chain-of-thought。
- Agent 直接写 SQLite。

## 2. Runtime 规格

### 2.1 Runtime 类型

```text
runtime = deterministic | langgraph_rag | langgraph_card | langgraph_study | langgraph_multi_agent
```

含义：

- `deterministic`：现有稳定 workflow。
- `langgraph_rag`：RAG Graph。
- `langgraph_card`：Card Graph。
- `langgraph_study`：Study Graph。
- `langgraph_multi_agent`：组合多个 subgraph 的多 Agent runtime。

### 2.2 Runtime 入口

保留现有入口：

```text
POST /workflows/knowledge-qa
POST /workflows/ai-card-generation
```

新增入口：

```text
POST /workflows/agent-task
```

`agent-task` 只处理复合任务。普通问答和普通制卡不强制经过 multi-agent。

### 2.3 Agent Task 输入

```json
{
  "runId": "string",
  "taskType": "qa | card_generation | study_diagnosis | compound_study_task",
  "question": "string | null",
  "documentIds": ["string"],
  "cardIds": ["string"],
  "options": {
    "allowCardCandidates": true,
    "allowLearningAdvice": true,
    "maxRetries": 1
  }
}
```

约束：

- `runId` 由 Rust 创建。
- `documentIds` 为空时由 Rust 按现有知识问答规则处理。
- `maxRetries` 第一版固定不超过 1。
- `allowCardCandidates=false` 时不得调用 Card Graph。

### 2.4 Agent Task 输出

```json
{
  "status": "completed | fallback | failed | cancelled",
  "runtime": "langgraph_multi_agent",
  "answerArtifactId": "string | null",
  "cardCandidateArtifactIds": ["string"],
  "learningAdviceArtifactId": "string | null",
  "traceArtifactId": "string | null",
  "errorCategory": "string | null",
  "fallbackUsed": false
}
```

## 3. 数据权威与持久化

### 3.1 权威边界

```text
React UI -> Rust Commands -> SQLite / Stronghold
                  ^
                  |
        Python Sidecar / LangGraph
```

规则：

- Rust/SQLite 是唯一数据权威。
- Python 通过 Host Gateway 请求读写。
- Python 不直接持久化业务实体。
- LangGraph checkpoint 生产环境经 Host Gateway 写入。
- API Key 仍由 Stronghold 保存，Python 只接收短时注入。

### 3.2 允许 Python 产生的结果

Python 可以产生：

- answer artifact。
- evidence artifact。
- card candidate artifact。
- learning advice artifact。
- trace artifact。
- workflow event summary。
- checkpoint summary。

Python 不可以直接产生：

- 正式 card 业务写入。
- review schedule 修改。
- provider config 修改。
- document / chunk 业务表直接写入。

## 4. Tool Spec

每个工具必须注册。

```python
class ToolSpec(BaseModel):
    tool_key: str
    description: str
    input_schema: str
    output_schema: str
    allowed_callers: list[str]
    side_effect: Literal[
        "none",
        "event_only",
        "checkpoint_only",
        "candidate_only",
        "persistent_via_rust"
    ]
    error_categories: list[str]
    retryable: bool
```

调用规则：

- 未注册工具拒绝。
- caller 不在 `allowed_callers` 内拒绝。
- 输入不符合 schema 拒绝。
- 输出不符合 schema 视为工具失败。
- `persistent_via_rust` 只表示可请求 Rust，不表示 Python 可写库。

## 5. Artifact 规格

### 5.1 通用 Artifact

```json
{
  "artifactId": "string",
  "artifactType": "evidence | answer | card_candidate | learning_advice | trace",
  "schemaVersion": 1,
  "createdBy": "rag_graph | card_graph | study_graph | multi_agent_graph",
  "summary": "string",
  "sourceRefs": [],
  "qualitySummary": {},
  "errorCategory": null,
  "createdAt": "ISO-8601"
}
```

不得包含：

- 完整 prompt。
- 完整 chain-of-thought。
- API Key。
- 未裁剪文档正文。
- 完整长会话历史。

### 5.2 Evidence Artifact

```json
{
  "artifactType": "evidence",
  "sourceRefs": [
    {
      "documentId": "string",
      "chunkId": "string",
      "pageStart": 1,
      "pageEnd": 1,
      "score": 0.82,
      "retrievalPath": "vector | fts5 | fusion"
    }
  ],
  "qualitySummary": {
    "retrievalMode": "hybrid",
    "vectorBackedCount": 5,
    "ftsOnlyCount": 2
  }
}
```

### 5.3 Card Candidate Artifact

```json
{
  "artifactType": "card_candidate",
  "sourceRefs": [
    {
      "documentId": "string",
      "chunkId": "string",
      "sourceQuote": "string"
    }
  ],
  "candidates": [
    {
      "front": "string",
      "back": "string",
      "sourceChunkId": "string",
      "sourceQuote": "string",
      "confidence": 0.85,
      "qualityFlags": []
    }
  ]
}
```

候选卡不是正式卡。正式卡写入必须由 Rust 校验后完成。

## 6. Graph State 规格

### 6.1 通用状态字段

```python
class BaseGraphState(TypedDict):
    run_id: str
    runtime: str
    graph_version: str
    user_intent: str | None
    document_scope: list[str]
    artifact_refs: list[str]
    diagnostics: dict
    error_category: str | None
    fallback_target: str | None
```

### 6.2 状态保存规则

checkpoint 只保存：

- graph version。
- current node。
- 可恢复状态摘要。
- artifact refs。
- diagnostics summary。
- fallback target。

不保存：

- 完整 prompt。
- 完整 LLM 消息列表。
- 未裁剪正文。
- API Key。

## 7. 错误分类

统一错误枚举：

```text
embedding_missing
embedding_stale
embedding_failed
retrieval_no_hits
no_relevant_content
provider_timeout
provider_auth_error
provider_rate_limited
invalid_json
schema_validation_failed
citation_invalid
source_quote_invalid
tool_not_registered
tool_input_invalid
tool_output_invalid
caller_not_allowed
context_budget_exceeded
checkpoint_write_failed
checkpoint_resume_failed
host_gateway_failed
workflow_cancelled
unknown_error
```

使用规则：

- 展示给用户的是可理解文案。
- event / checkpoint / artifact 记录枚举值。
- 原始异常只进开发日志，且不得包含密钥或正文。

## 8. UI 展示规格

第一阶段只展示摘要，不做复杂 Agent 调试面板。

### 8.1 RAG UI

展示：

- 回答。
- 引用卡片。
- 检索状态。
- 简短诊断：例如“已检索 5 个片段，引用 3 个”。

不展示：

- 完整 prompt。
- graph state。
- chain-of-thought。

### 8.2 候选卡 UI

展示：

- 候选卡 front / back。
- source quote。
- 接受 / 丢弃。
- 质量标签。

不展示：

- Critic 完整推理。
- Deduper 内部长文本。

### 8.3 Multi-Agent UI

展示：

```text
正在理解任务 -> 正在检索资料 -> 正在生成候选卡 -> 已完成
```

失败时展示：

- 哪个阶段失败。
- 是否已回退。
- 可重试动作。

## 9. 验收总表

| 项目 | 必须满足 |
| --- | --- |
| 数据边界 | Python 不直接写 SQLite |
| 密钥边界 | API Key 不进入 event / checkpoint / artifact |
| RAG | citation 只来自本轮证据 |
| 制卡 | source quote 可校验 |
| Multi-Agent | Router 不直接生成业务结果 |
| Checkpoint | 可恢复但不保存完整敏感内容 |
| Fallback | 任一新增 runtime 可降级 |
| UI | 默认只展示摘要级状态 |
