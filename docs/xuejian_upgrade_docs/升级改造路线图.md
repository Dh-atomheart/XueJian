# XueJian v2-vN 升级改造路线图

> 本文是后续开发的路线文档。它不替代 `docs/spec.md` 与 `docs/architecture.md`，只定义从现有 v1 到后续版本的渐进式升级顺序。原则是：每个版本只引入少量可验证改造，不一次性重构整个项目。

## 0. 阅读方式

- 只想知道方向：读「1. 总体目标」和「3. 版本路线」。
- 准备开发：读对应版本的「开发边界」和「验收标准」。
- 准备拆任务：结合《规格文档.md》《RAG升级技术文档.md》《多Agent升级技术文档.md》。

## 1. 总体目标

XueJian 后续升级的核心不是把项目变成通用聊天 Agent，而是增强学习闭环：

```text
PDF 导入 -> 文档解析 -> RAG 证据引擎 -> 学习问答 -> 候选制卡 -> 复习反馈 -> 学习诊断
```

升级后的系统应具备：

1. 问答有可靠证据。
2. 制卡来源可追溯。
3. 复习反馈能反哺补卡与学习建议。
4. LangGraph 负责流程编排，但不越过 Rust/SQLite 数据权威边界。
5. 每个版本可单独发布、回退和验收。

## 2. 技术基线

### 2.1 当前项目基线

现有 v1 已具备：

- Tauri / React / Rust / SQLite / Stronghold 本地优先架构。
- Python orchestration sidecar。
- PDF 文档解析。
- AI 制卡 workflow。
- Embedding 与知识问答 workflow。
- `workflow_runs` / `workflow_events` / `workflow_checkpoints` 基础。
- BYOK Provider 与 Stronghold 密钥边界。

不改变的边界：

- Rust/SQLite 仍是唯一数据权威。
- Python 不直接打开或写入 SQLite。
- API Key 不进入日志、checkpoint、event、prompt artifact。
- 前端不直接访问 SQLite 或持有明文密钥。

### 2.2 新增框架基线

建议新增：

```text
langgraph>=1.1.10,<2
langgraph-checkpoint>=4.1.0,<5
langchain>=1.2.18,<2
```

使用原则：

- LangGraph：承载 RAG graph、Card graph、Study graph、Multi-Agent graph。
- LangChain：只用于模型调用、工具包装、structured output 等能力。
- LiteLLM：保留现有 Provider 适配能力。
- Pydantic v2：统一输入输出 schema。

生产 checkpoint 不直接使用 Python 自有 SQLite。开发期可用 `InMemorySaver`，生产期实现 `HostGatewayCheckpointer`，由 Rust 写入现有 workflow checkpoint 表。

## 3. 版本路线

### V2：RAG Graph 骨架

目标：把现有知识问答 workflow 拆为 LangGraph 状态图，但不改变用户体验。

只做两件事：

1. 新增 `rag_graph`，替代 `knowledge_qa.py` 内部长流程。
2. 抽出 citation auditor 和 RAG trace。

不做：

- 多 Agent。
- 制卡改造。
- 长期记忆。
- 自动学习计划。
- 新 UI 面板。

开发边界：

```text
knowledge_qa.py -> 调用 rag_graph.invoke(...)
rag_graph 节点 -> 复用现有 Host Gateway
checkpoint -> 先摘要级保存
UI payload -> 保持兼容
```

验收标准：

- 原有知识问答功能可用。
- citation 仍只来自本轮 retrieved chunks。
- 未向量化文档不进入正式回答。
- provider timeout / invalid JSON / citation invalid 有稳定错误分类。
- 关闭 LangGraph 后可回退到原确定性 workflow。

### V3：Hybrid Retrieval 2.0

目标：提升召回质量，但不引入外部向量数据库。

只做两件事：

1. 将检索拆成 vector path + FTS5 path。
2. 用 RRF 合并候选结果。

不做：

- Milvus / Qdrant / ChromaDB 依赖。
- 复杂 rerank 默认开启。
- 跨文档自动研究。

开发边界：

```text
SQLite FTS5 = lexical path
现有 vector search = semantic path
RRF = rank fusion
正式 answer 必须有 vector-backed evidence
FTS-only 只能作为 excerpt_fallback 或诊断
```

验收标准：

- 术语型问题能被 FTS5 拉起候选。
- 概念型问题能被 vector 拉起候选。
- 最终 grounded answer 不使用 FTS-only。
- retrieval trace 能展示 dense、sparse、fusion 的摘要。

### V4：Query Rewrite + Relevance Gate + Parent Context

目标：解决追问、低相关误答、上下文不足。

只做三件事：

1. 多轮追问 query rewrite。
2. relevance gate 决定 answer / retry / reject。
3. 命中 leaf chunk 后补 parent context。

不做：

- 长期记忆。
- HyDE 默认开启。
- Agent 自由规划检索。

开发边界：

```text
query rewrite 只服务检索，不作为事实来源
parent context 只补上下文，不作为 citation source
citation 只允许 leaf chunk
低相关最多二次检索一次
```

验收标准：

- “它 / 这个 / 上一个”追问能稳定改写。
- 无关问题返回 `no_relevant_content`。
- 长段落解释更完整，但 citation 仍精确。
- context budget 超限时可诊断。

### V5：Card Graph 候选制卡

目标：把 AI 制卡从“一次生成”升级为“候选生成 + 来源校验 + 质量过滤”。

只做两件事：

1. 新增 `card_graph`。
2. 新增 `card_candidates` 或等价候选存储。

不做：

- 多 Agent supervisor。
- 自动学习计划。
- 用户长期画像。

开发边界：

```text
source mapping -> generate candidates -> source quote audit -> critique -> dedupe -> submit candidate
```

候选卡不直接污染正式 `cards`。正式入库仍由 Rust 校验，并可要求用户接受。

验收标准：

- 每张候选卡有 source chunk / source quote。
- source quote 不合法则候选卡不可入库。
- 低质量、重复、过宽泛卡片有可解释丢弃原因。
- 失败时不产生部分正式卡片写入。

### V6：Study Graph 学习反馈

目标：用复习记录生成轻量学习诊断，并能触发补卡建议。

只做两件事：

1. 新增 `study_graph` 读取复习反馈。
2. 输出弱点主题与补卡建议。

不做：

- 自动改复习计划。
- 自动调整 SM-2 / FSRS 参数。
- 长期记忆自动写入。

开发边界：

```text
review history -> weak topic summary -> optional evidence retrieval -> suggested card gaps
```

验收标准：

- 能基于错题、低评分、重复失败识别薄弱主题。
- 建议可以触发 Card Graph 生成候选卡。
- 学习建议默认不写入长期记忆。
- 失败不影响问答和复习主流程。

### V7：Multi-Agent Orchestrator

目标：将 RAG、Card、Study 三个 graph 组合成受控多 Agent 协作。

只做两件事：

1. 新增 Router / Supervisor。
2. 组合已有 subgraph，而不是重写业务逻辑。

不做：

- 开放任意工具调用。
- Agent 之间自由聊天。
- 自动写库。
- 复杂 UI 调试台。

协作形态：

```text
Router
  -> Knowledge Agent = rag_graph
  -> Card Agent = card_graph
  -> Learning Agent = study_graph
  -> Trace Reporter = trace summary
```

验收标准：

- 普通问答仍走 RAG Graph。
- 普通制卡仍走 Card Graph。
- 只有复合任务走 Multi-Agent Orchestrator。
- 任一子图失败可降级，不影响其他已完成结果。
- Router 不直接生成答案或卡片。

### V8+：Memory 与个性化增强

目标：在系统稳定后加入可控记忆与个性化。

只做两件事：

1. 会话摘要用于 query rewrite 与表达风格。
2. 长期偏好只影响风格和难度，不作为事实来源。

不做：

- 保存完整文档正文。
- 保存完整 chain-of-thought。
- 记忆作为 citation。
- 自动推断敏感画像。

验收标准：

- 用户可查看、禁用、删除记忆。
- 记忆与 retrieved evidence 冲突时，以 evidence 为准。
- 记忆不进入引用体系。

## 5. 全局验收门槛

任何版本合入前必须满足：

- 不绕过 Rust/SQLite 权威层。
- 不记录 API Key。
- 不保存完整 prompt、完整 chain-of-thought、未裁剪敏感正文。
- 所有 LLM 输出进入业务前必须 schema 校验。
- 所有 citation / source quote 必须由后端校验。
- 所有新增 workflow 有失败分类与 fallback。
- 原有 PDF、卡片、复习主流程不被破坏。
