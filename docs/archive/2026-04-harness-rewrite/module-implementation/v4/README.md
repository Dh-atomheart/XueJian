# V4阶段模块实施索引

## 阶段目标

V4 进一步把学习材料结构化为知识图谱，并补齐主题切换与跨端能力评估，不以正式 Android 上线为验收标准。

本阶段延续 [ai-architecture-decision.md](../../ai-architecture-decision.md) 的协议复用硬约束：桌面端使用本地 Python 服务，未来移动端复用协议与任务语义，而不是强制复用桌面进程形态。

## 模块顺序

1. [V4-1 知识图谱模块](./v4-1-knowledge-graph.md)
2. [V4-2 主题切换与扩展主题模块](./v4-2-theme-switching-and-theme-packs.md)
3. [V4-3 Android能力适配评估模块](./v4-3-android-capability-assessment.md)

## 依赖关系

- `V4-1` 依赖 `V2-1` 的知识范围和 `V3-2` 的聚合内容
- `V4-2` 依赖 `M1` 已落地的默认设计系统和页面壳层
- `V4-3` 依赖所有 MVP 核心能力的真实实现状况

## 建议实施顺序

- 先完成 `V4-1` 图谱抽取和存储
- 再实现 `V4-2` 的主题切换与扩展包
- 最后输出 `V4-3` 的跨端能力矩阵和迁移建议

## 当前阶段实施重点

- `V4-2` 只负责主题切换与扩展，不得回头重新定义 MVP 默认视觉
- `V4-3` 输出的是评估结论和迁移方案，不是 Android 客户端开发计划
- `V4-3` 必须把协议复用、Host 能力抽象和 Python 服务替代形态作为核心评估项
