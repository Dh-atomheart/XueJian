# V4-3 Android能力适配评估模块实施计划

## 模块定位

- `Module ID`: `V4-3`
- `Stage`: `V4`
- `Priority`: `P4`
- `Spec Reference`: `spec.md` §2.5.3、§5.4、§6.5
- `Depends On`: `M1`、`M2`、`M3`、`M4`、`M5`、`M6`
- `Blocks`: 未来移动端立项

## 交付目标

- 评估桌面端能力向 Android 迁移的可行性
- 输出能力矩阵、阻塞项、替代方案和优先级建议
- 把“协议复用硬约束”写清：Android 复用 `Orchestration Protocol`、任务语义和数据契约，而不是强制复用桌面 Python 进程形态

## Done Means

- 输出能力矩阵和阻塞项清单
- 明确哪些能力可复用、哪些能力需要重写、哪些能力只复用协议
- 形成 Android 迁移建议，而不是直接实现客户端

## 前置条件

- MVP 核心能力已具备真实实现形态
- `V4-2` 主题扩展与默认设计系统规则已固定

## 交付物

- 文档层：平台能力矩阵、阻塞项清单、迁移建议
- 技术层：关键接口清单、协议复用清单、平台替换点、风险分级
- 测试层：兼容性检查结果与验证记录

## 接口与数据契约

- 公共业务类型：`PlatformCapabilityProfile`
- 关键契约：
  - 评估结果必须明确 `supports*` 类能力边界
  - 输出不是代码实现，而是迁移方案与阻塞项
  - Android 迁移必须保留 `Orchestration Protocol`、任务语义与核心数据契约
- 模块内部实施类型：
  - `MigrationRiskItem`
  - `PlatformGapCategory`
  - `RuntimeReplacementOption`

## 数据流 / 交互流

1. 盘点桌面端现有能力
2. 映射到 Android 能力矩阵
3. 标记可复用、需替换、仅协议复用、不可行项
4. 汇总阻塞项和替代方案
5. 输出迁移建议与优先级

## 异常与边界

- 本模块不实现 Android 客户端
- 不承诺上线时间，只输出评估与建议
- 不应为适配 Android 反向破坏桌面端当前架构
- 不再把“是否无 sidecar”作为唯一判断标准

## 测试矩阵

- 文档检查：能力矩阵完整性、阻塞项完整性、协议复用说明完整性
- 一致性检查：与 `spec.md` 和 `ai-architecture-decision.md` 的跨端约束保持一致
- 风险检查：文件系统、后台任务、PDF、TTS、Python 服务替代形态等高风险点均有结论
