# V4-2 主题切换与扩展主题模块实施计划

## 模块定位

- `Module ID`: `V4-2`
- `Stage`: `V4`
- `Priority`: `P3`
- `Spec Reference`: `spec.md` §2.5.2、§5.4、§6.5
- `Depends On`: `M1`
- `Blocks`: 无

## 交付目标

- 在不改变 MVP 默认视觉基线的前提下，提供主题切换与扩展主题包能力
- 支持默认主题、扩展主题包和无障碍回退主题
- 保证主题切换不改变业务组件接口与交互结构

## Done Means

- 用户可在主题间切换
- 默认主题可回退
- 阅读、学习、设置等关键界面切换后仍可用且可读

## 前置条件

- `M1` 已完成默认设计系统、字体槽位、纸感壳层和基础 primitives
- `M4`、`M5`、`M6` 已在默认视觉系统下落地

## 交付物

- 代码层：ThemeProvider、主题注册、切换状态持久化
- 资源层：扩展主题包规范、Token 覆盖与资源映射
- 测试层：回退主题、对比度、阅读效率回归测试

## 计划改动路径

- `xuejian/src/design-system/`
- `xuejian/src/components/shell/`
- `xuejian/src/assets/themes/`

## 接口与数据契约

- 公共业务类型：复用 `ThemeTokens`、`SketchStyle`、`SurfaceVariant`、`PageShellVariant`
- 关键契约：
  - 主题包只能覆盖 Token 和资源，不得改变业务组件 API
  - 默认主题永远存在且可回退
  - 主题切换状态应持久化到设置层
- 模块内部实施类型：
  - `ThemePackManifest`
  - `ThemeSelectionState`

## 数据流 / 交互流

1. 应用读取当前主题设置
2. ThemeProvider 加载默认主题或扩展主题包
3. 页面和组件读取新 Token
4. 用户切换主题时即时更新并持久化
5. 若主题异常，则回退默认主题

## 异常与边界

- 不允许借主题扩展重写阅读器布局或学习主流程
- 不允许删除默认主题
- 视觉切换不能降低 PDF 正文、卡片正文和表单可读性

## 测试矩阵

- 单元：主题注册、设置持久化、回退逻辑
- 集成：主题切换后阅读页、学习页、设置页一致更新
- 视觉验收：默认主题、扩展主题、高对比主题的对比度和效率
