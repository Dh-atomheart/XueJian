## 模块定位

- `Module ID`: `V4-1`
- `Stage`: `V4`
- `Priority`: `P3`

## 交付目标

- 从文档、卡片、问答与播客内容中抽取知识节点和关系
- 提供可回溯来源、可增量更新的图谱结构
- 采用 `LangChain-first` 的抽取工作流，保留未来复杂化时升级 `LangGraph` 的可能

## Done Means

- 图谱可构建、可增量更新、可回溯来源
- 同义概念能做基本消歧与合并
- UI 能浏览节点、关系和来源

## 前置条件

- `V2-1` 已提供知识范围、引用和命中内容
- `V3-2` 已提供聚合后的长内容材料

## 接口与数据契约

- 公共业务类型：`KnowledgeNode`、`KnowledgeEdge`、`GraphBuildRun`
- 关键契约：
  - 每个节点和边都应保留 `sourceIds`
  - `GraphBuildRun` 必须记录构建状态
  - 图谱 UI 不得展示无法回溯来源的强结论
  - 抽取工作流通过 Host 调用模型与检索能力
- 模块内部实施类型：
  - `EntityCandidate`
  - `DisambiguationDecision`
  - `ExtractionBatch`

## 数据流 / 交互流

1. 用户选择知识范围
2. Python 工作流抽取实体与关系
3. Host 执行消歧辅助、持久化和状态更新
4. 写入节点与边
5. UI 展示图谱并支持回查来源

## 异常与边界

- 不允许把模型猜测当作无来源事实展示
- 图谱更新失败时不得破坏既有稳定图结构
- 消歧结果必须可重跑和修正
- 若后续流程明显演化为复杂分支图，再单独评估 LangGraph 升级
