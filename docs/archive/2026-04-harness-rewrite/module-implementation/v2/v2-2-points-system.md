# V2-2 积分系统模块实施计划

## 模块定位

- `Module ID`: `V2-2`
- `Stage`: `V2`
- `Priority`: `P1`
- `Spec Reference`: `spec.md` §2.3.2、§5.2、§6.3
- `Depends On`: `M5`
- `Blocks`: 无

## 交付目标

- 为学习行为提供轻量激励，而不改变主学习闭环
- 建立可审计、可防重、可撤销的积分账本
- 在不引入复杂游戏化系统的前提下提供基础成就反馈

## Done Means

- 学习行为可生成积分
- 同一事件不会重复记账
- UI 可查看积分、连续天数和基础成就

## 前置条件

- `M5` 已稳定产出 `ReviewLog`、今日统计与学习事件
- MVP 首页和设置页已有可扩展的反馈区域

## 交付物

- 数据层：`PointLedger`、`RewardEvent`
- 业务层：积分规则、防重策略、签到计算
- UI层：积分显示、简单成就页、连续学习提示
- 测试层：记账、防刷分、撤销场景

## 接口与数据契约

- 公共业务类型：`PointLedger`、`RewardEvent`
- 关键契约：
  - 所有积分变化必须带 `reason`
  - 同一 `sourceId` 只能记账一次
  - 不直接维护“总分表”替代账本
- 模块内部实施类型：
  - `RewardRule`
  - `StreakSnapshot`

## 数据流 / 交互流

1. 学习行为完成
2. 系统评估是否触发积分与成就
3. 写入 `PointLedger`
4. 可选生成 `RewardEvent`
5. UI 展示积分变化和 streak

## 异常与边界

- 不允许在前端直接修改总分
- 不允许重复提交造成重复积分
- 奖励反馈必须轻量，不应盖过学习主流程

## 测试矩阵

- 单元：规则映射、去重、连续天数计算
- 集成：复习事件到账本、撤销异常记账
- 视觉验收：积分反馈保持克制，不破坏默认视觉基线
