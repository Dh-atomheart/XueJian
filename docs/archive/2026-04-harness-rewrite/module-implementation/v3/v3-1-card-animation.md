# V3-1 卡片动画生成模块实施计划

## 模块定位

- `Module ID`: `V3-1`
- `Stage`: `V3`
- `Priority`: `P2`
- `Spec Reference`: `spec.md` §2.4.1、§5.3、§6.4
- `Depends On`: `M3`
- `Blocks`: 无

## 交付目标

- 将适合可视化表达的卡片转为动画预览资源
- 建立脚本生成、渲染执行和资源管理的闭环
- 保证失败可回退、资源可重试和可清理

## Done Means

- 用户可从卡片发起动画生成
- 动画可预览、可重生成、可删除
- 失败任务保留足够上下文以便排查和重试

## 前置条件

- `M3` 已提供稳定的卡片详情和长任务运行时
- 已具备本地资源落盘与任务恢复能力

## 交付物

- 代码层：内容分析、脚本生成、渲染执行环境、预览组件
- 数据层：`AnimationJob`、`AnimationAsset`
- 测试层：生成、失败回退、资源清理测试

## 接口与数据契约

- 公共业务类型：`AnimationJob`、`AnimationAsset`
- 关键契约：
  - `AnimationJob.status = queued | running | completed | failed`
  - 所有产物都必须登记为 `AnimationAsset`
- 模块内部实施类型：
  - `AnimationIntent`
  - `RenderSandboxResult`

## 数据流 / 交互流

1. 用户在卡片详情页点击生成动画
2. 系统分析内容并生成动画脚本
3. 渲染执行环境产出预览资源
4. UI 展示动画预览
5. 用户可重试、替换或删除资源

## 异常与边界

- 不允许直接执行未经约束的任意生成脚本
- 失败任务必须保留日志和脚本，不得静默吞错
- 资源删除必须同时清理文件与数据库索引

## 测试矩阵

- 单元：内容分析、脚本生成、资源登记
- 集成：渲染执行、失败回退、重试覆盖
- 视觉验收：预览组件与默认视觉系统协调
