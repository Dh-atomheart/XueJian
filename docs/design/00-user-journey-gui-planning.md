# 前端 GUI 用户操作流程与功能设计总纲

## 1. 产品目标与设计原则

### 1.1 文档目标

本规划文档面向产品、设计与前端团队，用于在当前产品能力基础上统一前端 GUI 的任务链路、页面职责与交互规则。文档不按代码模块拆分，而按用户完成任务的连续动作组织，作为后续 PRD、信息架构、线框图、高保真 UI 与前端任务拆分的共同基线。

### 1.2 规划范围

- 正式规划模块：Home、Library、Reader、Card Studio、Review、Knowledge QA、Knowledge Graph、Podcast、Settings、Profile。
- Knowledge 模块在产品层应视为 `Knowledge QA + Knowledge Graph` 的双子页，而不是两个顶层导航。
- Reader 不是顶层导航页，而是文档域中的深任务页。当前实现中关闭 Reader 默认回到 Library；后续设计应尽量在从 Home、QA、Graph 跳入时保留来源上下文。
- 旧版 `GraphPage` 或实验性质页面不纳入本次正式规划。

### 1.3 产品目标

- 让新用户可以在首次进入后快速完成 AI 配置、导入文档并进入第一条学习闭环。
- 让高频用户能从首页和文库快速进入阅读、卡片生成、复习与知识加工，不被复杂仪表盘干扰。
- 让所有异步任务具备阶段反馈、失败恢复入口与明确下一步动作，减少“任务做了一半不知道去哪”的中断感。
- 让桌面端承载完整信息密度与双栏操作，移动端保留主任务闭环并允许简化复杂审核流。

### 1.4 设计原则

- 任务优先：页面首先服务于完成动作，不为展示信息而展示信息。
- 上下文连续：文档、卡片、问答、图谱、播客之间的跳转尽量保留当前文档、当前选区、当前会话。
- 状态清晰：空、加载、成功、失败、无配置、不可用六类状态统一表达。
- 页面访问权限与 AI 能力可执行性必须分离描述：`no_ai_config` 不等于页面不可进入。
- 导航规则统一为软提示：任何“去设置”CTA 都是可选引导，而不是全局门禁。
- 桌面优先：优先保证桌面端双栏、预览、批量处理效率；移动端做减法而不是照搬。
- 可恢复：所有长任务和异步任务都必须提供阶段反馈、错误说明、重试或替代路径。

## 2. 用户类型与高频任务

### 2.1 新用户

- 目标：建立可用的 AI/BYOK 能力，成功导入首个文档，理解产品主链路；未完成配置时也能先浏览主要页面。
- 高频任务：进入 Home、查看配置提醒、跳转 Settings、回到 Library 导入文档、进入 Reader。

### 2.2 学习执行用户

- 目标：每天快速完成待学习任务并查看进度反馈。
- 高频任务：从 Home 进入 Review、完成一轮会话、回到 Home 或 Profile 查看结果。

### 2.3 内容加工用户

- 目标：把文档转为可学习卡片或可听化内容。
- 高频任务：从 Library 或 Reader 进入 Card Studio、审核候选卡片、发起 Podcast 生成、处理失败任务。

### 2.4 知识探索用户

- 目标：围绕文档做问答、证据追溯与概念浏览。
- 高频任务：在 Knowledge QA 中提问、查看 citation 并跳转 Reader、在 Knowledge Graph 中浏览节点并继续追问。

## 3. 五条核心用户旅程

### 3.1 旅程一：新用户首次进入并完成系统准备

- 触发入口：首次打开应用，或 Home 上检测到无 AI 配置。
- 用户目标：建立可用的 AI 环境，并知道第一步该做什么。
- 前置条件：应用已安装并可启动。
- 标准步骤：
  1. 用户进入 Home，看到欢迎态、缺少 AI 配置提醒和“去设置”主按钮。
  2. 用户进入 Settings，先完成供应商配置、Key 存储、连接测试和默认配置设定。
  3. 用户继续完成 workflow assignment，确保文档处理、问答、卡片、播客有默认工作流。
  4. 用户保存成功后回到 Home，系统将首页提醒切换为“去导入第一份文档”。
  5. 用户点击进入 Library，开始导入首个文档。
- 异常分支：
  - 连接测试失败：停留在 Settings 当前表单，展示失败原因、重试按钮和文档链接位。
  - 仅配置了 Key 但未配置 workflow：Home 仍保留提醒，提示“已完成基础连接，仍需分配工作流”。
  - 宿主服务不可用：顶部全局告警条提示服务异常，允许重试或查看日志面板。
- 完成标志：至少存在一个通过连接测试的默认 AI 配置，且关键 workflow 已分配。
- 下一步推荐动作：导入第一份文档并进入阅读。

### 3.2 旅程二：导入文档并进入阅读

- 触发入口：Home 的快捷动作、Library 空状态导入入口、最近文档区域。
- 用户目标：把文档导入系统并开始阅读。
- 前置条件：用户本地有可导入文档；若后续需要发起 AI 动作，再要求存在可用 AI 配置。
- 标准步骤：
  1. 用户在 Library 点击导入，选择文件并提交。
  2. 系统展示 processing 状态，说明正在解析文档、提取结构、生成 anchors/chunks。
  3. 文档进入列表，用户可在文库中看到状态、基础元信息和预览卡。
  4. 文档状态变为 ready 后，主操作切换为“继续阅读”。
  5. 用户进入 Reader，默认定位到第一页或最近阅读位置，开始阅读。
- 异常分支：
  - 文档处理中：列表可见进度、不可进入深度功能，但允许返回 Home 或切换其他文档。
  - 文档处理失败：展示 error 状态、失败原因摘要和“重新处理/删除/查看详情”。
  - 自动卡片生成失败：不阻断阅读路径，但给出 warning，并推荐去 Card Studio 手动继续。
- 完成标志：用户成功进入 Reader 并看到文档内容。
- 下一步推荐动作：做高亮摘录、发起卡片生成，或继续问答。

### 3.3 旅程三：从文档生成卡片并完成筛选确认

- 触发入口：Library 文档操作、Reader 文本选区动作、Home 快捷动作、Card Studio 主入口。
- 用户目标：把 ready 文档转成可入库学习卡片。
- 前置条件：至少有一份 ready 文档。
- 标准步骤：
  1. 用户进入 Card Studio，优先看到 ready 文档选择器。
  2. 用户选择文档，设定生成数量，确认开始生成。
  3. 系统展示任务阶段、进度和 checkpoint 恢复能力。
  4. 候选卡片生成后，用户逐张浏览或批量筛选。
  5. 用户对候选卡片执行编辑、接受、拒绝。
  6. 用户点击 finalize，系统把已接受卡片入库并回写结果。
- 异常分支：
  - 无 ready 文档：展示空状态，引导去 Library 完成导入或等待处理完成。
  - 候选卡片为空：展示“本次未产出有效候选”，推荐调高数量、调整文档或回到 Reader 选区生成。
  - 生成任务失败：展示失败原因、重试、恢复 checkpoint 或更换工作流。
- 完成标志：至少一张候选卡片被接受并成功入库。
- 下一步推荐动作：立即进入 Review，或回 Reader 补充摘录。

### 3.4 旅程四：进入复习并完成学习反馈

- 触发入口：Home 今日任务卡片、Review 主入口、卡片入库成功后的 CTA。
- 用户目标：完成当日新卡与复习卡的学习反馈。
- 前置条件：用户已有待学习卡片。
- 标准步骤：
  1. 用户从 Home 进入 Review，先看到会话摘要，包括新卡数、复习卡数和预计时长。
  2. 用户开始会话，进入单卡模式。
  3. 用户先阅读正面内容，再执行翻面。
  4. 翻面后系统展示 `again / hard / good / easy` 四档评分。
  5. 用户持续完成一轮评分，直到会话结束。
  6. 系统展示完成页，总结本轮数量、正确趋势和连续学习状态。
- 异常分支：
  - 无待学习卡：Review 显示空状态并推荐去 Card Studio 或 Library。
  - 学习中断：保留当前卡索引和会话进度，下次进入继续。
  - 保存反馈失败：本地先暂存评分并提示同步重试。
- 完成标志：会话进入 complete 状态并写入学习反馈。
- 下一步推荐动作：返回 Home 查看剩余任务，或进入 Profile 查看长期表现。

### 3.5 旅程五：针对文档发起知识问答、播客生成或知识图谱探索

- 触发入口：Library 文档快捷动作、Reader 选区动作、Knowledge 模块、Podcast 模块。
- 用户目标：围绕已导入文档进行问答、关系探索或内容转听。
- 前置条件：至少一份 ready 文档；若要执行 QA、图谱或播客等 AI 动作，还需要相关工作流已配置。页面本身可先进入并展示说明。
- 标准步骤：
  1. 用户从文档上下文进入 Knowledge QA、Knowledge Graph 或 Podcast。
  2. 若是 QA，用户输入问题，可选限定文档范围，等待有 citation 的回答。
  3. 若是 Graph，用户选文档发起图谱生成，然后浏览节点、关系和来源。
  4. 若是 Podcast，用户填写风格、时长、语言、TTS 等参数并发起生成。
  5. 用户根据结果继续跳转 Reader 查看来源、回到 QA 深挖问题，或试听播客成品。
- 异常分支：
  - orchestration 失败：展示失败原因、重试、重启服务或切换工作流。
  - 图谱尚未生成：展示引导态和立即生成入口。
  - 播客生成中断：保留任务记录，允许恢复、重试或删除。
- 完成标志：用户获得一个可消费结果，包括答案、图谱浏览结果或 ready 音频。
- 下一步推荐动作：回 Reader 追溯来源、生成卡片、继续下一轮问答。

## 4. 页面级详细操作流程

### 4.1 Home

- 页面目标：作为学习控制台，承接今日任务、最近文档和高频动作，不承担复杂数据分析。
- 主要用户：新用户、每日学习用户、高频回访用户。
- 主要入口：应用启动默认页、学习完成后的返回页。
- 页面分区：
  - 顶部标题与全局提醒区。
  - 今日待学习任务总览区。
  - 最近文档区。
  - 快捷动作区。
  - AI 配置提醒区。
  - 学习连续性与积分摘要区。
- 核心操作顺序：
  1. 首次进入先判断是否缺少 AI 配置。
  2. 若缺配置，主 CTA 为“去设置完成系统准备”。
  3. 若已有内容，第一屏优先展示“开始今日学习”和“继续最近文档”。
  4. 无内容用户看到导入引导，不展示空洞仪表盘。
  5. 用户从快捷动作进入 Library、Review、Card Studio 或 Knowledge。
- 关键状态：
  - 首次进入欢迎态。
  - 无文档空状态。
  - 有文档但无待学习任务状态。
  - 有待学习任务状态。
  - 无 AI 配置提醒状态。
  - 宿主服务异常状态。
- 反馈机制：
  - 轻量成功操作用 toast。
  - AI 缺配置与服务异常用顶部 notice/card 持续展示。
  - 高频入口点击后立即提供页面切换反馈。
- 常见误操作与防呆：
  - 用户误以为首页可以完成所有流程时，应明确把按钮文案写成“去文库导入”“去复习”“去设置”。
  - 当无待学习卡时，禁用“开始复习”并改为“暂无任务，去生成卡片”。
- 与其他页面的跳转关系：
  - 跳转 Settings 处理缺配置。
  - 跳转 Library 导入或继续文档。
  - 跳转 Review 执行学习。
  - 跳转 Card Studio 继续卡片生产。

### 4.2 Library

- 页面目标：作为文档总入口与预处理中心，承接导入、状态识别、预览与分流。
- 主要用户：新用户、内容加工用户、知识探索用户。
- 主要入口：Home 导入入口、主导航切换、导入完成回流。
- 页面分区：
  - 导入区。
  - 文档列表区。
  - 状态过滤与搜索区。
  - 文档预览区。
  - 文档快捷动作区。
- 核心操作顺序：
  1. 空状态时优先展示导入引导。
  2. 有文档时按最近访问或状态排序展示列表。
  3. 选中文档后，在右侧预览区展示摘要、状态与可执行动作。
  4. ready 文档可进入 Reader、Card Studio、Knowledge QA。
  5. processing/error 文档优先处理状态问题，而不是强行跳转深任务页。
- 关键状态：
  - 无文档。
  - processing。
  - ready。
  - error。
  - 多文档混合状态。
- 反馈机制：
  - 导入后立即插入列表并显示 processing 标签。
  - 状态变化用列表高亮或 notice 更新。
  - 错误文档需有可展开详情。
- 常见误操作与防呆：
  - processing 文档禁用进入卡片和问答，避免用户误判系统卡死。
  - 删除文档需二次确认，并说明会影响卡片、问答、图谱和播客关联结果。
- 与其他页面的跳转关系：
  - 跳转 Reader。
  - 跳转 Card Studio。
  - 跳转 Knowledge QA。
  - 从 Reader 关闭后默认回到此页。

### 4.3 Reader

- 页面目标：提供深度阅读、标注和知识提炼联动空间。
- 主要用户：深度阅读用户、卡片加工用户、知识探索用户。
- 主要入口：Library 文档打开、QA citation 跳转、Graph 来源跳转。
- 页面分区：
  - 顶部文档操作栏。
  - 中央文档阅读画布。
  - 左右侧工具栏或侧栏。
  - 注释/卡片联动区。
- 核心操作顺序：
  1. 打开后默认显示第一页或最近阅读位置。
  2. 用户通过翻页、缩放、页码定位控制阅读。
  3. 选中文本后弹出动作菜单。
  4. 用户可高亮、写注释、生成卡片、发起问答。
  5. 侧栏同步显示注释和相关卡片上下文。
  6. 关闭 Reader 时返回 Library；若从其他模块进入，应保留返回来源标识。
- 关键状态：
  - 首次打开加载中。
  - PDF 渲染成功。
  - 选区动作激活。
  - 无注释状态。
  - 来源定位状态。
- 反馈机制：
  - 翻页与缩放即时反馈。
  - 高亮成功用局部提示，不打断阅读。
  - 生成卡片/问答动作触发后给出侧边任务反馈。
- 常见误操作与防呆：
  - 未选中文本时隐藏上下文动作，避免出现无效按钮。
  - 离开页面前若注释未保存，提示是否保存草稿。
- 与其他页面的跳转关系：
  - 跳转 Card Studio 继续审核卡片。
  - 跳转 Knowledge QA 继续提问。
  - 关闭后回到 Library，后续建议支持回到发起来源。

### 4.4 Card Studio

- 页面目标：作为候选卡片生成、审核与入库中心。
- 主要用户：内容加工用户、需要做大批量学习准备的用户。
- 主要入口：主导航、Library 文档动作、Reader 选区动作、导入后的自动衔接提示。
- 页面分区：
  - 文档选择与参数配置区。
  - 任务进度区。
  - 候选卡片列表区。
  - 单卡编辑区。
  - 批量操作区。
- 核心操作顺序：
  1. 先判断是否有 ready 文档。
  2. 用户选择文档并填写生成数量。
  3. 发起任务后进入运行态，显示阶段反馈和 checkpoint。
  4. 任务完成后进入候选审核态。
  5. 用户批量接受/拒绝，必要时逐张编辑。
  6. finalize 后显示入库结果和后续 CTA。
- 关键状态：
  - 无 ready 文档空状态。
  - 参数待提交状态。
  - generating。
  - review candidates。
  - finalize success。
  - finalize failed。
- 反馈机制：
  - 长任务用进度条、阶段标签、剩余预估。
  - 批量操作后即时刷新统计数。
  - finalize 成功后给出“去复习”“回阅读器”“继续生成”。
- 常见误操作与防呆：
  - 数量输入越界时即时校验。
  - 生成中禁止重复提交。
  - 批量拒绝大量卡片时允许撤销一次。
- 与其他页面的跳转关系：
  - 无文档时跳转 Library。
  - 成功后跳转 Review。
  - 可回 Reader 继续提取更多内容。

### 4.5 Review

- 页面目标：执行学习任务，不混入内容生产和文档管理。
- 主要用户：每日复习用户、完成卡片入库后的学习用户。
- 主要入口：Home 今日任务、Card Studio finalize 成功页、主导航。
- 页面分区：
  - 会话介绍区。
  - 单卡展示区。
  - 翻面与评分区。
  - 会话完成总结区。
- 核心操作顺序：
  1. 进入后先看到本轮学习摘要。
  2. 点击开始，进入单卡正面。
  3. 用户翻面查看答案。
  4. 用户在底部固定区点击 `again / hard / good / easy`。
  5. 系统更新下一次调度并进入下一张。
  6. 完成后进入总结页。
- 关键状态：
  - intro。
  - studying-front。
  - studying-back。
  - complete。
  - 无任务空状态。
- 反馈机制：
  - 每次评分后即时切卡并短暂提示记忆反馈已记录。
  - 完成页展示数量、连续天数、积分变化。
- 常见误操作与防呆：
  - 未翻面前不展示评分按钮，避免误点。
  - 退出中途会话时提示保留进度。
- 与其他页面的跳转关系：
  - 返回 Home。
  - 跳转 Profile 查看长期表现。
  - 无任务时跳转 Card Studio 或 Library。

### 4.6 Knowledge QA

- 页面目标：提供基于已导入内容、带出处的问答体验。
- 主要用户：知识探索用户、深度阅读用户。
- 主要入口：Knowledge 模块默认子页、Library 文档动作、Reader 选区动作。
- 页面分区：
  - 问题输入区。
  - 文档范围筛选区。
  - 处理中反馈区。
  - 答案区。
  - citation 区。
- 核心操作顺序：
  1. 默认进入自由问答模式，文档范围为“全部可用文档”。
  2. 用户可改为限定单篇或多篇文档。
  3. 提交问题后进入 orchestration 处理中状态。
  4. 成功后先展示答案，再展示 citation 列表与来源片段。
  5. 用户点击 citation 一键进入 Reader 对应位置。
  6. 用户可基于当前答案继续追问。
- 关键状态：
  - 默认待输入状态。
  - 文档限定状态。
  - processing。
  - answer ready。
  - orchestration failed。
  - 服务不可用。
- 反馈机制：
  - 处理中要显示阶段文字与轮询状态，而不是静态 loading。
  - 成功答案区与 citation 区层级明确，citation 始终可见。
  - 失败时必须提供“重试”“重启服务”“检查配置”。
- 常见误操作与防呆：
  - 无可用文档时禁用提问并引导去 Library。
  - 输入为空时禁用提交。
  - citation 缺失时必须标记“答案缺少可追溯来源，不建议直接用于学习”。
- 与其他页面的跳转关系：
  - 跳转 Reader 查看来源。
  - 跳转 Knowledge Graph 继续概念探索。
  - 可回到原始文档上下文。

### 4.7 Knowledge Graph

- 页面目标：作为概念与关系浏览空间，不承担文档导入管理。
- 主要用户：知识探索用户、需要理解结构关系的用户。
- 主要入口：Knowledge 模块二级子页、QA 延展入口、Library 文档动作。
- 页面分区：
  - 图谱生成入口区。
  - 图谱画布区。
  - 节点详情区。
  - 来源追溯区。
- 核心操作顺序：
  1. 若目标文档无图谱，先展示引导态和“立即生成”。
  2. 用户选择文档后发起生成或增量构建。
  3. 图谱 ready 后，用户在画布上浏览节点与关系。
  4. 点击节点后侧栏展示定义、关系与来源。
  5. 用户可从节点跳回 Reader 或转到 QA 继续追问。
- 关键状态：
  - 未生成。
  - 生成中。
  - 已生成可浏览。
  - 节点详情展开。
  - 构建失败。
- 反馈机制：
  - 生成中展示构建阶段、取消入口和最近更新时间。
  - 节点点击后突出选中状态与来源数。
  - 失败时提供重试或切换文档。
- 常见误操作与防呆：
  - 无 ready 文档时不显示空白画布，而是展示导入引导。
  - 节点过多时默认聚类或分层，避免首次即信息过载。
- 与其他页面的跳转关系：
  - 跳转 Reader 查看来源。
  - 跳转 Knowledge QA 追问节点相关问题。
  - 可回 Library 切换文档。

### 4.8 Podcast

- 页面目标：把文档内容转为可听化产物，覆盖参数配置、生成、review 与试听。
- 主要用户：内容加工用户、希望通勤或碎片时间学习的用户。
- 主要入口：主导航、Library 文档动作、Reader 文档上下文推荐。
- 页面分区：
  - 新建播客参数区。
  - 任务列表区。
  - 任务详情与阶段状态区。
  - 试听播放器区。
- 核心操作顺序：
  1. 用户先选择 ready 文档。
  2. 依次配置风格、时长、语言、TTS、输出格式。
  3. 提交后创建任务并进入 outline、script、review、audio 等阶段。
  4. 若任务到达 review 节点，用户先确认脚本再继续。
  5. ready 后用户可试听、重新生成或进入播放器。
  6. failed/cancelled 任务可恢复、重试或删除。
- 关键状态：
  - 无 ready 文档空状态。
  - 参数填写中。
  - generating-outline。
  - generating-script。
  - awaiting-review。
  - rendering-audio。
  - ready。
  - failed。
  - cancelled。
- 反馈机制：
  - 任务列表明确展示阶段名，不只显示统一 loading。
  - ready 后自动展示首段试听入口。
  - 失败任务在列表中保留，避免“消失式失败”。
- 常见误操作与防呆：
  - 参数未填全时禁用生成。
  - 生成中防止重复提交相同文档与相同参数。
  - 删除任务需二次确认。
- 与其他页面的跳转关系：
  - 从 Library 带入文档上下文。
  - 从 ready 音频可回文档或去 Profile 查看成果累计。

### 4.9 Settings

- 页面目标：作为系统配置中心，以 AI/BYOK 与 workflow assignment 为核心。
- 主要用户：新用户、需要排查连接问题的用户、高级用户。
- 主要入口：Home 配置提醒、主导航、QA/Podcast/Card Studio 异常恢复入口。
- 页面分区：
  - AI 配置区。
  - Workflow assignment 区。
  - 学习偏好区。
  - 播客偏好区。
  - 通用设置区。
- 核心操作顺序：
  1. 首次进入时先展示 onboarding 提示。
  2. 用户新建供应商配置，录入 Key 并测试连接。
  3. 连接成功后设为默认配置。
  4. 用户继续分配 workflow 到文档处理、问答、卡片、播客等链路。
  5. 用户再调整学习与播客偏好。
  6. 保存后回到发起页面继续原任务。
- 关键状态：
  - 首次 onboarding。
  - 草稿未保存。
  - 测试连接中。
  - 测试成功。
  - 测试失败。
  - workflow 未完整分配。
- 反馈机制：
  - 连接测试结果需要带响应时间、模型可用性和失败摘要。
  - 保存成功用 toast，且要即时更新“AI 能力已启用”提示状态。
- 常见误操作与防呆：
  - 未测试成功前不能设为默认。
  - 未完成关键 workflow assignment 时，离开页面前提醒。
  - 高风险操作如清缓存、重置配置需二次确认。
- 与其他页面的跳转关系：
  - 从 Home、QA、Podcast、Card Studio 异常状态回流。
  - 保存后应尽量返回用户原发起页。

### 4.10 Profile

- 页面目标：展示学习结果、连续性与长期成长反馈，并把用户导回行动页。
- 主要用户：高频学习用户、想复盘进度的用户。
- 主要入口：Review 完成页、主导航、Home 成长摘要点击。
- 页面分区：
  - 学习统计总览区。
  - 连续天数与热力图区。
  - 积分/成长摘要区。
  - 最近成果入口区。
- 核心操作顺序：
  1. 用户先看到最近学习结果和连续天数。
  2. 进一步查看积分、掌握度、最近成果。
  3. 页面底部或侧边始终给出“继续今日任务”“回文库”“继续问答”等推荐动作。
- 关键状态：
  - 有统计数据。
  - 新用户空状态。
  - 同步延迟状态。
- 反馈机制：
  - 数据更新后用轻量提示标明“已同步到最新学习结果”。
  - 空状态提供首个行动建议，而不是仅显示 0 数据。
- 常见误操作与防呆：
  - 统计指标名必须可解释，避免只有术语没有说明。
  - 空状态时不展示复杂图表占位。
- 与其他页面的跳转关系：
  - 跳转 Home 继续任务。
  - 跳转 Library 查看最近成果对应文档。
  - 跳转 Review 开始下一轮学习。

## 6. 全局状态与反馈规范

### 6.1 导航规则

- 桌面端左侧主导航固定承担主模块切换，避免同层级重复入口分散。
- 顶部标题区统一承担页面名称、功能摘要、全局提醒和当前上下文对象。
- Knowledge 在导航层表现为一个模块，在页面内部再分为 QA 与 Graph 两个子页签。
- Reader 不出现在主导航中，应通过 Library、QA citation、Graph 来源等上下文入口进入。

### 6.2 状态规则

- 空状态：必须说明“为什么当前为空”和“下一步去哪里”，不能只显示插画。
- 加载状态：短加载用 skeleton，长任务用阶段反馈、进度、耗时或轮询状态。
- 失败状态：必须包含失败原因摘要、重试入口和替代路径。
- 无配置状态：必须明确当前未启用的是 AI 能力而非整页访问权限，并提供直达 Settings 的 CTA。
- `no_ai_config` = AI 能力未启用，不等于页面不可进入。
- `workflow_unassigned` = 部分 AI 工作流未就绪，不等于整站不可用。
- `service_unavailable` = 服务异常，应显示告警与重试，不自动改写导航。
- 无权限或宿主服务不可用状态：必须落到全局可见的告警区，不允许静默失败。

### 6.3 反馈规则

- 轻量成功操作使用 toast 或 notice，不打断主任务。
- 高风险失败必须进入可查看的反馈面板，例如任务详情、日志抽屉或错误卡片。
- 关键链路失败必须附带下一步动作，如“去设置检查工作流”“返回文库重试处理”“重新启动服务”。
- 用户完成一个闭环后，必须展示下一步推荐动作，而不是停在孤立成功页。

### 6.4 异步任务规则

- 文档导入、卡片生成、QA orchestration、图谱构建、播客生成都属于长任务，统一要求显示：
  - 当前阶段。
  - 是否可取消。
  - 最近更新时间。
  - 失败恢复入口。
- 任务失败后不移除原记录，避免用户误以为任务未提交。
- 可恢复任务优先恢复 checkpoint 或保留参数，不要求用户重复填写。

### 6.5 跳转与上下文规则

- 任意深任务页都应给出“回退到上一步”和“继续下一步”的双出口。
- 文档、卡片、问答、图谱、播客之间跳转时，优先保留当前文档对象。
- 从 Reader 进入其他任务时，保留页码、选区、注释上下文。
- 当前实现中 Reader 关闭默认回 Library；设计稿中应为来自 QA/Graph/Home 的进入方式预留返回来源能力。

### 6.6 异常场景基线

- 无文档：Home、Library、QA、Graph、Podcast、Profile 都要有明确引导。
- 文档处理中：Library 中可见进度，相关深任务功能禁用但不隐藏。
- 文档处理失败：提供重试、删除、查看详情。
- 无 AI 配置：Home 和相关业务页统一显示提醒卡、顶部 notice 或内联空态，并提供可选的 Settings 入口，不强制回流。
- 工作流执行失败：保留任务记录，允许重试或调整 workflow。
- 网络或宿主服务不可用：顶部全局告警条 + 页面内局部错误态双重提示。
- 候选卡片为空：Card Studio 提供替代动作，不以成功页收尾。
- 播客生成中断：保留任务并支持恢复、重试、删除。

## 7. 桌面优先 / 移动兼容规则

### 7.1 桌面端原则

- 默认采用左侧导航、顶部标题、主内容区、辅助侧栏的布局。
- Library、Reader、Card Studio 优先支持双栏或多区并行，提升预览和审核效率。
- QA、Graph、Podcast 的任务详情与结果区可以同屏展示，减少来回切页。

### 7.2 移动端原则

- 只保留核心任务动作，不复制桌面端全部信息密度。
- 导航采用底部主入口或横向页签，避免保留完整左侧导航。
- 高密度表格、双栏预览、复杂候选列表改为分步流。
- Reader 保留阅读、翻页、基础高亮和“生成卡片/提问”主动作，不强求完整侧栏联动。
- Card Studio 在移动端优先支持“单张审核流”，批量操作弱化为次级入口。
- Graph 在移动端优先提供节点详情浏览，不强求大画布复杂拖拽。

### 7.3 响应式优先级

- 必须完整支持：Home、Library 导入、Reader 阅读、Review 学习、QA 提问、Settings 基础配置。
- 可以简化支持：Card Studio 批量审核、Graph 深度浏览、Podcast 复杂任务管理。
- 不应在移动端缺席任何主链路，只允许降级交互复杂度。

## 9. 后续 UI 设计与开发拆分建议

### 9.1 设计产出建议

- 第一阶段先产出信息架构图和 5 条用户旅程蓝图，确保跨页动作闭环。
- 第二阶段按页面优先级输出线框图：Home、Library、Reader、Card Studio、Review、Knowledge、Podcast、Settings、Profile。
- 第三阶段统一状态组件规范：空状态、任务卡、错误卡、顶部提醒、任务进度条、二级操作栏。
- 第四阶段补高保真 UI，并明确桌面版与移动版差异。

### 9.2 前端实现拆分建议

- 先做全局壳层规范：导航、标题区、全局提醒、错误面板、统一状态组件。
- 再做文档域闭环：Home 到 Library 到 Reader 到 Card Studio。
- 然后做学习闭环：Card Studio finalize 到 Review 到 Profile。
- 最后做知识加工闭环：Knowledge QA、Knowledge Graph、Podcast，以及与 Reader 的上下文联动。

### 9.3 联调与验收建议

- 以 5 条核心旅程做走查，不以单页静态完成度作为唯一标准。
- 每条旅程都要验证异常分支是否可恢复。
- 桌面端优先验收完整闭环，移动端验收核心动作是否仍可完成。

### 9.4 与现有设计文档的关系

- 本文档是现有 `docs/design/01-09` 单页设计文档的上位总纲。
- 单页文档继续承担具体页面布局与局部组件说明。
- 本文档负责统一跨页动作、异常恢复、上下文保留与模块边界，避免后续设计口径漂移。
