# Study 模块设计

Study 模块负责每日复习、调度、四档反馈和学习统计。它的目标是让用户上手即用，不需要理解调度算法。

## 目标

MVP 目标是跑通稳定的学习闭环：

- 用户启用或暂停分组。
- 系统从启用分组中选出今日到期卡片。
- 用户按四档反馈完成复习。
- 系统更新下一次复习时间。
- 首页展示学习热力图、完成数、学习时长、连续天数和进度。

## 不做什么

MVP 不做：

- 复杂记忆模型预测分析。
- 成就系统。
- points/积分系统。
- 高级队列排序策略。
- 用户可见的复杂 FSRS 参数面板。
- 多设备学习记录同步。

## 当前决策

- 调度底层采用 Rust FSRS 或等价后端实现。
- Rust 后端是复习调度权威。
- 前端 `ts-fsrs` 冻结为参考或测试对照，不作为最终状态源。
- UI 四档反馈为 `忘记 / 模糊 / 记得 / 熟练`。
- 内部映射为 `again / hard / good / easy`。
- 每日队列来自启用分组中的到期卡。
- 用户可调每日新卡上限和复习卡上限。
- 默认上限：新卡 20，复习 100。
- 到期卡过多时最早到期优先。
- 学习统计以 `study_events` 为事实来源。

## 核心流程

### 生成每日队列

```text
读取启用 CardGroup
-> 查询 group 内 due <= now 的 ReviewState
-> 按 due 升序排序
-> 应用每日复习上限
-> 补充新卡到每日新卡上限
-> 返回 StudyQueue
```

暂停分组的卡片不进入今日复习。

### 提交复习反馈

```text
用户查看卡片
-> 用户选择四档反馈
-> Rust 映射 again/hard/good/easy
-> 调度器计算新的 ReviewState
-> 写入 ReviewState
-> 追加 StudyEvent
```

`StudyEvent` 是统计事实来源，不应通过只改汇总表绕过事件记录。

### 学习统计

统计从 `study_events` 推导：

- 每日完成卡片数。
- 学习时长。
- 连续学习天数。
- 正确率或熟练度。
- 文档进度。
- 分组进度。

如未来引入汇总缓存表，缓存必须可从 `study_events` 重建。

## 数据与状态

核心实体：

- `CardGroup`：学习队列来源。
- `Card`：复习对象。
- `ReviewState`：当前调度状态。
- `StudyEvent`：复习事实记录。

关系：

```text
CardGroup -> Card -> ReviewState -> StudyEvent
```

`ReviewState` 应保留 FSRS 兼容字段，例如：

```text
state
difficulty
stability
due
last_review
reps
lapses
```

字段级 schema 后续由数据库 baseline 文档确定。

## 与其他模块的边界

- Cards 提供卡片和分组。
- Study 不关心 PDF 解析细节。
- Study 不直接调用 AI。
- Settings 提供每日新卡上限、复习上限和学习偏好。
- 首页统计消费 Study 输出，但不拥有统计事实。

## MVP 验收场景

- 用户启用一个分组后，该分组到期卡进入今日复习。
- 用户暂停一个分组后，该分组卡片不进入今日复习。
- 用户完成四档反馈后，系统更新下一次复习时间。
- 系统记录一条 `StudyEvent`。
- 今日复习遵守默认新卡 20、复习 100 的上限。
- 首页统计能从学习事件展示热力图、完成数、总时长和连续天数。

## 后续待细化问题

- Rust FSRS crate 或等价实现选择。
- 新卡与复习卡混排策略。
- 学习时长计算口径。
- 分组掌握进度计算口径。
- 离线时间和跨时区展示策略。
