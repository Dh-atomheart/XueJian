# UI-01：Shell 与可见文案基线

## 目标

让当前应用先符合 MVP UI 边界，消除明显违背规范的问题，为后续主题和页面改造提供稳定入口。

## 所属阶段

UI 改造路线，MVP 基线加固。

## 相对工作量

M。

## 前置条件

- 阅读 `docs/ui.md`。
- 阅读 `docs/学习工作台_交互界面设计规范_v1.0.md`。
- 按 `docs/reuse-strategy.md` 审计 AppShell、导航、设置页和冻结页面入口。

## 交付内容

- 主导航固定为 `首页 / 文档 / 卡片 / 学习 / 设置`。
- Reader 继续从文档或来源进入，不作为主导航项。
- Reader 模式隐藏主 Sidebar。
- 清理 AppShell、导航、状态条和主要入口中的用户可见乱码文案。
- 隐藏 `podcast / animation / points / export / profile` 的 MVP 主入口。
- 保留历史代码，但不让冻结功能出现在默认导航、首页任务卡、设置 tab。

## 任务分配

### Frontend

- 收敛 AppShell 导航定义和页面元信息。
- 修复 Shell、导航、运行状态提示、移动导航中的乱码文案。
- 检查首页、设置页和主要入口是否暴露冻结功能。
- Reader 打开时保持沉浸模式。

### Rust/Tauri

- 无新增任务。

### Python orchestration

- 无新增任务。

### Data/Schema

- 无新增任务。

### Tests

- 导航项测试。
- Reader 沉浸模式测试。
- 冻结入口不可见测试。
- 关键中文文案断言，防止乱码回归。

## 不做什么

- 不重构主题系统。
- 不新增 Knowledge/RAG 主导航。
- 不删除冻结模块历史代码。
- 不迁移组件目录。

## 验收场景

- 用户打开应用只看到五项 MVP 主导航。
- 点击五项主导航均进入对应页面。
- 用户打开 Reader 后主侧栏隐藏。
- 主导航和 Shell 无用户可见乱码。
- 冻结功能没有默认入口。

## 风险与回退

- 历史测试仍断言冻结页面入口：同步调整测试目标为“历史代码可存在，但默认入口不可见”。
- 乱码文案分散：先修用户第一屏和导航，再按页面逐步收敛。
