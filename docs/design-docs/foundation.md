# 设计基础与视觉叙事

## 1. 产品气质

学笺不是企业后台，也不是泛知识内容站。它更接近一张被整理过的学习书桌：

- 有纸感和留白，但不是复古拟物
- 有手绘墨线感，但不是儿童化插画
- 有学习反馈和工具感，但不是仪表盘式驾驶舱

用户打开应用时，第一感受应该是：

`这是一个为专注阅读、摘取知识、反复记忆而设计的桌面工作台。`

## 2. 主记忆点

产品的主记忆点固定为：

`纸感工作台 + 细墨线工具界面 + 贴笺式学习上下文`

三者缺一不可：

- 没有纸感，界面会退化成普通后台模板
- 没有细墨线，界面会失去辨识度
- 没有贴笺式上下文，产品会失去学习场景的独特体验

## 3. 核心场景

设计必须优先服务以下五个动作：

1. 进入首页，快速知道今天该做什么
2. 上传文档并理解当前处理状态
3. 在阅读页把原文和卡片关联起来
4. 在学习页高效完成一轮 FSRS 复习
5. 在设置页安全配置 BYOK 和检查连接状态

## 4. 设计原则

### 4.1 正文优先于壳层

- PDF 正文、卡片正反面、设置表单文本必须优先保证清晰度
- 任何纹理、贴纸、手绘线、纸张阴影都不能盖过正文信息层级

### 4.2 装饰只为增强场景，不为炫技

- 装饰重点放在外层容器、分隔、贴笺表面、按钮轮廓、标题下划线
- 禁止在内容区大面积使用杂色背景、涂鸦覆盖或高噪点纹理

### 4.3 密度克制，但不能空泛

- 页面应显得轻盈、易读、有留白
- 同时必须保有明确工具感，不能被做成只有氛围没有信息密度的展示页

### 4.4 学习流程要有节奏

- 首页进入、阅读联动、翻卡、评分、保存配置都应提供轻量反馈
- 动效用于说明“状态变化”，不是为了制造存在感

### 4.5 多栏是默认工作模式

- 桌面端默认按“导航轨 + 主画布 + 上下文侧栏”组织
- 单栏只能作为小屏退化方案，不能反向成为主设计心智

### 4.6 手绘感必须有边界

允许：

- 导航图标轮廓
- 按钮边框和 hover 轮廓
- 标题下划线
- 贴笺卡片边线
- 弱化分隔和标记

禁止：

- 正文主字体手写化
- 表单控件结构失真
- 数据表述依赖装饰线解释
- 阅读热区和文本选区被纹理覆盖

## 5. 页面共性规则

## 5.1 Shell 结构

- 左侧 `SidebarRail` 保持窄轨工具感，承担全局导航，不承载说明性长文本
- 顶部 `TopBar` 保持低高度，负责当前页面名称、工具动作和弱状态信息
- 主画布承担主要任务，信息密度最高
- `ContextRail` 只在需要上下文联动的页面出现，当前 MVP 重点是阅读页

## 5.2 视觉层级

从高到低排序：

1. 正文内容与关键任务
2. 当前交互对象
3. 次级状态和工具动作
4. 壳层表面与分隔
5. 纹理与装饰

## 5.3 状态设计

每个核心页面都要定义至少以下状态中的一个子集：

- `first-use`
- `empty`
- `loading`
- `processing`
- `success`
- `error`

状态提示应遵循：

- 优先告诉用户现在发生了什么
- 再告诉用户还要等什么
- 最后给出下一步动作

## 5.4 响应式策略

- `> 1280px`：完整三栏或双栏
- `1024px - 1280px`：隐藏 `ContextRail`，保持主任务完整
- `< 1024px`：只保留最低可用桌面退化，不为 MVP 定义触屏优先布局

## 5.5 动效规则

允许：

- 页面进入时 120-240ms 渐入和轻微位移
- 阅读联动时 160-220ms 高亮过渡
- 学习卡片翻面时 180-260ms 变换
- 成功保存、上传完成、评分提交时的轻量反馈

禁止：

- 弹跳式大位移动画
- 高频连续闪烁
- 与学习任务无关的装饰性粒子、漂浮物和背景动画

## 5.6 可访问性底线

- 正文与背景至少保持稳定可读对比
- 图标按钮实际点击热区不小于 `36px`
- 重要交互必须有键盘焦点态
- 学习页评分按钮不能只靠颜色区分
- 右侧贴笺和顶部状态不能替代正文中的核心信息

## 6. Do / Don't

### Do

- 用纸感底色和细墨线建立统一身份
- 让阅读页和学习页始终保持专注模式
- 用标题、边界和留白组织结构，而不是依赖重底色
- 把异步状态说清楚，让用户知道任务还在继续

### Don't

- 不要做成企业后台首页式卡片矩阵
- 不要把手绘感直接压到正文和表单控件上
- 不要为“好看”牺牲 PDF 阅读和翻卡节奏
- 不要使用紫白渐变、重玻璃拟态、过度阴影等通用 AI 风格
